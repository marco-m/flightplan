# flightplan

Generate Concourse pipelines programmatically with Go.

WORK IN PROGRESS. NOT USABLE.

This work stems from the realization that configuration files in YAML (or in JSON) become unmanageable as soon as the file gets long enough. In particular, Concourse pipelines tend to be big and so difficult to edit; even worse attempting to keep multiple pipelines to use the same patterns.

Instead, generating a pipeline configuration programmatically, with a statically typed language, allows to:

- Handle complexity and refactoring with a programming language: full editor support, Language Server support.
- Handle duplication with a programming language: instead of YAML anchors, just use a language variable.
- Handle "customizing" pieces of pipelines with a programming language, instead of YAML anchors or YAML manipulation.

In particular with Go:

- Handle common code in multiple pipelines in different repositories as an external Go package: `go get site/common-code` (see examples). This is the same approach of [Florist](https://github.com/marco-m/florist).

## Navigable, line-scoped errors like a compiler

The errors printed by Flightplan:
- are clickable in any editor or terminal
- point to the exact line where the API caused the error
- like a compiler, attempt to keep going and print multiple errors

## Consistency and semantic checks

Flightplan performs many consistency and semantic checks before hitting the Concourse server (hint: this overlaps partially with OPA, which Concourse supports, worthile to consider).

- Many consistency checks reported by Flightplan are not detected by Concourse (they are discovered by the user at runtime).
- Many error messages returned by Flightplan are clearer than the ones returned by Concourse.

## Flightplan extensions

### Generation of task files

Concourse supports two types of task configurations: inline in the pipeline or as an external task file.

Using an external task file is a prerequisite to be able to use `fly execute`, which is fundamental for quick iterations while developing or debugging pipelines.

If struct `Task` has fields `File` and `FileConfig` filled, then Flightplan will generate the task file.

If on the other hand only field File is filled, then Flightplan will assume that the task file is written OOB (or even generated by Flightplan in another `Task` of the same pipeline), thus it will behave as a normal Concourse pipeline.
